# Architecture

Project KillChain Hub is an npm-workspaces monorepo with two deployables and a
shared seed dataset.

```
project-killchain-hub/
├── apps/
│   ├── api/          Express + TypeScript (CJS) + better-sqlite3 + Zod
│   └── web/          React 19 + Vite + Tailwind + Framer Motion
├── data/             SQLite database (generated by npm run seed)
├── scripts/          Stdlib-only Python tooling for indicator lists
├── docs/             This folder
└── .github/          CI + templates
```

## Request flow

```
Browser ──► Vite dev server (:5173)
              │  /api/* proxied (VITE_API_PROXY)
              ▼
           Express (:4000)
              │  helmet → cors → json → routes → error handler
              ▼
           SQLite (data/killchain.db, WAL)
```

- The web client always calls relative `/api/...` paths. In development Vite
  proxies them to `http://localhost:4000` (`apps/web/vite.config.ts`); in
  production nginx or your reverse proxy does the same.
- Every response is JSON except the export endpoints (`/iocs/export`,
  `/reports/:id/markdown`) which stream files with `Content-Disposition`.
- Errors use a single envelope: `{ "error": { "message", "code", "details?" } }`.
  The web `ApiError` class unwraps it, and a `401` clears the session and
  dispatches `pkc:unauthorized` so `AuthContext` can redirect to `/login`.

## API layering (`apps/api/src`)

| Layer | Files | Responsibility |
| --- | --- | --- |
| Entry | `index.ts` | Config, DB warm-up, listen, graceful shutdown |
| App | `app.ts` | Middleware, route mounts (`requireAuth` on everything except `/api/auth` and `/api/health`) |
| Routes | `routes/*.ts` | Zod validation, permission gates (`canWrite`, `isAdmin`), SQL, serialization |
| Middleware | `middleware/auth.ts`, `middleware/error.ts` | JWT verification, role rank, error normalization |
| Schemas | `schemas.ts` | Request/query schemas shared by routes |
| DB | `db/index.ts`, `db/seed.ts` | Schema DDL, migrations-on-boot, synthetic seed data |
| Utils | `utils/*.ts` | IOC validation, CSV/JSON codecs, JWT, IDs, activity logging, report markdown |

SQLite runs in WAL mode with prepared statements everywhere — no ORM, no
migrations framework; `CREATE TABLE IF NOT EXISTS` keeps the schema stable and
the seed script is idempotent.

### Data model

| Table | Purpose |
| --- | --- |
| `users` | Accounts (bcrypt hashes), role `admin \| contributor \| viewer` |
| `iocs` | Indicators: type, value, family, category, severity, confidence, first/last seen, tags, source |
| `hunts` | Detection hunts: query language, logic, references, MITRE tags |
| `articles` | Research write-ups (markdown body), slug + excerpt |
| `tools` | Curated tooling directory with categories and stars |
| `resources` | Learning resources (docs, blogs, labs, certifications) |
| `reports` | Assessment reports: metadata + findings JSON + CVSS stats |
| `submissions` | Community review queue (pending/approved/rejected) |
| `activity` | Append-only audit feed (`actor`, `action`, `subject`, `detail`) |

## Web layering (`apps/web/src`)

```
lib/          pure helpers: api client, types, format, markdown, highlight, qs
hooks/        useQuery, useDebounced, useCopy, useHotkeys, useLocalStorage
contexts/     Theme, Toast, Auth
components/
  ui/         primitives: Button, Modal, DataTable, Tabs, Tooltip, … (barrel index.ts)
  layout/     AppShell, Sidebar, Topbar, CommandPalette, Breadcrumbs
pages/        route-level screens (iocs/ holds drawer + modals for the hub page)
```

Design system rules:

- All colors come from CSS custom properties (`--c-*`, `--sev-*`) declared for
  dark (`:root`) and light (`html.light`). Tailwind maps them to
  semantic utilities (`bg-surface`, `text-ink-2`, `border-line`, `text-critical`…)
  with full alpha support, so **no `dark:` variants are used**.
- Motion is 150–250 ms with the shared `ease-smooth` curve; everything respects
  `prefers-reduced-motion`.
- Auth tokens live in `localStorage` (`pkc.token`, `pkc.user`); theme and
  sidebar preferences have their own keys and are applied pre-paint by an
  inline script in `index.html` to avoid flashes.

### State & data

- Server state: the tiny `useQuery` hook (fetch + abort + nonce refetch) — no
  cache library; each route mounts fresh and URL params (`qs()`) are the source
  of truth for filters, which makes every view shareable.
- Client state: React context (auth/theme/toast) + local `useState`; forms are
  controlled components submitting through footer buttons (`type="submit"
  form="…"`).
- The command palette (`⌘K`) hits `/api/search` which returns grouped results
  (iocs, hunts, articles, tools, resources, reports, submissions) and navigates
  with `?focus=<id>` deep-links.

## Testing strategy

- **API** — vitest + supertest-style `app.test.ts` covering auth, every CRUD
  route, permission denial, exports, search and dashboard aggregates.
- **Web** — vitest unit tests for pure modules (`lib/*.test.ts`).
- **Tooling** — the Python scripts are exercised against a full export
  (CSV → STIX → CSV round-trip) in CI-style smoke runs.
